# Что изменено в проекте

Дата: 22.10.2026

Ниже перечислены все изменения, внесённые в проект. Изменения сгруппированы
по файлам и сопровождаются кратким обоснованием.

## 1. Краткое резюме

Проект доведён до состояния, пригодного для запуска, сопровождения и передачи:

- устранены расхождения между кодом и пояснительной запиской;
- добавлен единый LLM-клиент с поддержкой Ollama и OpenAI-совместимого API
  (подготовка к развёртыванию на нейрокомпьютере ЧелГУ);
- исправлена логика статусов и дублирования запросов в чат-боте;
- улучшен алгоритм контекстных сниппетов;
- добавлена генерация черновиков процессуальных документов с экспортом в DOCX;
- добавлены тесты, README и пример конфигурации;
- повышена переносимость: пути, драйвер браузера, адрес LLM и параметры
  сервера вынесены в переменные окружения.

## 3. Изменённые файлы

### `config.py`

- Все пути теперь вычисляются относительно каталога проекта (`BASE_DIR`),
  а не текущего рабочего каталога.
- Добавлены переменные окружения:
  `LLM_PROVIDER`, `LLM_MODEL`, `OLLAMA_HOST`, `OPENAI_API_KEY`,
  `OPENAI_BASE_URL`, `LLM_TIMEOUT`, `LLM_MAX_RETRIES`,
  `PARSER_HEADLESS`, `PARSER_PAGE_TIMEOUT`, `QUERY_LOGS_DB`,
  `HOST`, `PORT`, `RELOAD`, `RUN_PIPELINE_ON_START`.
- Добавлены безопасные парсеры значений (`_env_bool`, `_env_int`,
  `_env_float`), чтобы некорректная переменная не роняла приложение.
- `EDGE_DRIVER_PATH` больше не является единственным вариантом: если файл
  не найден, используется Selenium Manager.
- `CORS_ORIGINS` корректно разбирается и игнорирует пустые элементы.

### `llm_client.py` (новый)

- Поддержка двух провайдеров:
  - `ollama` — локальный сервер Ollama;
  - `openai` — vLLM/TGI/Ollama `/v1` и другие OpenAI-совместимые API.
- Ленивая инициализация клиента и повторные попытки при сетевых ошибках.
- Очистка ответа от `<think>...</think>` и markdown-ограждений.
- `get_llm_info()` используется в `/api/health`.

### `reformulator.py`

- Удалён прямой импорт `ollama.chat`; все вызовы идут через `llm_client`.
- Добавлена функция `reformulate_with_status()`, которая возвращает не только
  запросы, но и признак успешной работы LLM.
- `reformulate_with_fallback()` сохранён для обратной совместимости.
- Улучшена обработка пустых ответов и ошибок.

### `chatbot.py`

- Используется `reformulate_with_status()`.
- Исправлен статус запроса: `error_api` теперь выставляется только при
  реальной ошибке LLM, а не при совпадении переформулировки с исходным
  запросом.
- Переформулированные запросы дедуплицируются; повторный поиск по исходному
  запросу не выполняется.
- Упрощена логика формирования `reformulated_queries` для ответа и логов.

### `search_engine.py`

- Удалены дублирующие реализации RRF и сниппетов; используются функции из
  `utils.py`.
- RRF теперь считается отдельно для каждого запроса, а затем оценки
  суммируются. Это корректнее, чем объединение всех кандидатов в один список.
- Запросы дедуплицируются.
- Добавлена проверка наличия файлов индексов с понятным сообщением.
- Добавлена проверка согласованности числа векторов FAISS и числа чанков.
- Усилена проверка пути при выдаче документа.

### `utils.py`

- Добавлены `dedupe_preserve_order()`, `reciprocal_rank_fusion()` и
  `make_context_snippet()`.
- Сниппеты теперь ищут позиции слов через регулярные выражения, поэтому
  корректно работают с несколькими пробелами и переводами строк. Ранее
  позиции вычислялись вручную и могли смещаться.

### `create_index.py`

- Индексируются только файлы `.txt`; бинарные и служебные файлы игнорируются.
- Пустые документы и пустые чанки пропускаются.
- Добавлена понятная ошибка, если нет документов или чанков.
- В `chunks_data.pkl` сохраняются имя модели эмбеддингов и параметры чанкинга.
- Число кластеров IVF ограничено 256 (как в коде), `nprobe` — 32.
- Кодирование выполняется с `batch_size=64`.

### `parser.py`

- Добавлены CLI-параметры `--limit`, `--max-categories`, `--max-pages`,
  `--headless`, что позволяет собирать как полный корпус, так и небольшой
  демонстрационный набор.
- `EDGE_DRIVER_PATH` проверяется: если драйвер не найден, используется
  Selenium Manager.
- Добавлен headless-режим (`PARSER_HEADLESS=true`) для серверного запуска.
- Таймаут загрузки страницы вынесен в `PARSER_PAGE_TIMEOUT`.
- Реестр URL сохраняется атомарно через временный файл и `os.replace`.
- Повреждённый `parsed_urls.json` больше не роняет парсер.
- Исправлен флаг логирования Edge (`--log-level=3`).
- Добавлена защита от пустого slug при сохранении документа.

### `query_logger.py`

- Путь к базе читается из `QUERY_LOGS_DB` при каждом подключении, что упрощает
  тестирование и перенос.
- Добавлены `timeout=10` и `PRAGMA busy_timeout=5000` для устойчивости при

### `scheduler.py`

- `stop_scheduler()` не падает, если планировщик не запущен.
- Логирование ошибок дочерних процессов стало информативнее.

### `app.py`

- Каталог шаблонов определяется относительно `app.py`.
- Версия API поднята до `5.0.0`.

  - `POST /api/documents/export`.

### `templates/index.html`

## 4. Изменения поведения

1. Поиск по переформулированным запросам больше не дублирует исходный запрос.
2. RRF суммируется по запросам, а не по общему списку кандидатов.
3. Статус `error_api` выставляется только при отказе LLM.
4. Сниппеты корректно работают на текстах с переносами строк.
5. При отсутствии индексов приложение сообщает об этом понятной ошибкой,
   а не падает с необработанным исключением.
6. При недоступности LLM документ формируется по шаблону и возвращается с
   предупреждением.
7. Генерация документа не сохраняет персональные данные на диск.
8. Проверяются ссылки на статьи: если норма не встречается в найденных
   прецедентах, документ получает предупреждение о необходимости ручной
   проверки.
9. Дублирующийся заголовок документа удаляется из сгенерированного текста.
10. В ответ чата добавляется предупреждение, если языковая модель сослалась
    на нормы, которых нет в найденных фрагментах.
11. Ответы бота рендерятся как Markdown: заголовки `###`, нумерованные и
    маркированные списки, `**жирный текст**`; HTML экранируется.

## 6. Что не изменялось и почему

- **Полный корпус данных.** Для проверки собрано 346 реальных судебных
  решений и построен индекс на 14 323 чанка. Полный корпус (~25 тыс.
  документов) не собирался: это занимает около 17 часов. Для расширения
  выполните `python parser.py` без `--limit` и `python create_index.py`.
- **Развёртывание на нейрокомпьютере.** Подготовлена конфигурация и поддержка
  OpenAI-совместимого API, но физическое развёртывание требует доступа к
  GPU-серверу вуза.
- **Аутентификация.** Не добавлялась: её лучше реализовать на уровне
 reverse-proxy или инфраструктуры вуза, чтобы не дублировать механизмы SSO.
- **CUDA-сборка PyTorch.** Установлен `torch 2.14.1+cpu`; индексация
  выполнялась на CPU. Для ускорения на RTX 4070 SUPER можно отдельно
  поставить CUDA-сборку PyTorch, но текущего времени индексации (~4 минуты
  на 14 тыс. чанков) достаточно для демонстрационного корпуса.

## 8. Как откатить

Проект не находится под Git, поэтому автоматического отката нет. Изменения
носили аддитивный характер: новые файлы можно удалить, а изменённые модули
восстановить из исходной копии, если она сохранилась. Перед дальнейшими
экспериментами рекомендуется инициализировать Git:

```bash
git init
git add .
git commit -m "Baseline after refactoring"
```
