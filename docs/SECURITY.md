# Безопасность

Документ фиксирует результаты аудита версии 5.1 и правила эксплуатации.
Проект рассчитан на учебную и опытно-эксплуатационную нагрузку; перед публикацией
в интернете обязательны меры из раздела «Развёртывание».

## Что было исправлено

| № | Проблема | Было | Стало |
| --- | --- | --- | --- |
| 1 | XSS в списке прецедентов | имя файла вставлялось в `onclick="openDoc('...')"`; апостроф в имени ломал строку | `data-filename` + делегирование, отдельное экранирование атрибутов |
| 2 | Админ-эндпоинты без защиты | `/api/logs`, `/api/log-stats`, `/api/reload-index` отдавали персональные запросы и позволяли перезагружать индекс кому угодно | необязательный `ADMIN_TOKEN`; при заданном токене доступ только по `X-Admin-Token` или `Bearer` |
| 3 | Неограниченный размер запроса | JSON любого размера принимался в память | лимит `MAX_REQUEST_BYTES` (1 МБ), ответ 413 |
| 4 | Отсутствие rate limit | один клиент мог бесконечно вызывать LLM | 60 запросов/мин на IP, 15/мин для LLM-эндпоинтов, ответ 429 с `Retry-After` |
| 5 | Блокировка event loop | `async def` эндпоинты вызывали синхронные FAISS/LLM | эндпоинты переведены в sync-def, Starlette выполняет их в threadpool |
| 6 | Утечка деталей ошибок | `detail=f"Ошибка перезагрузки: {exc}"` | общий текст 500, подробности только в лог |
| 7 | Path traversal в документах | проверка только по префиксу строки | `Path.resolve()` + `relative_to()` + строгий шаблон имени |
| 8 | Неконсистентный снимок индекса | reload менял `index`, `chunks`, `bm25` по одному | единый снимок под `RLock`, подмена одной операцией |
| 9 | Битые файлы после сбоя | индекс и тексты писались поверх | атомарная запись через `.tmp` + `os.replace` |
| 10 | Рост памяти сессий | сессии не ограничивались | `CHAT_MAX_SESSIONS`, периодическая очистка, TTL |
| 11 | Падение чата при сбое БД | исключение `log_query` рвало ответ | логирование изолировано, чат отвечает |
| 12 | SQL-инъекции | — | все запросы параметризованы; проверено |
| 13 | Утечка секретов | `OPENAI_API_KEY` не выводится в `/api/health` | в ответе только провайдер, модель и URL |
| 14 | Нет защитных заголовков | — | CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` |
| 15 | Подделка IP через прокси | — | `X-Forwarded-For` учитывается только при `TRUST_PROXY=true` |

## Остаточные риски

1. **Публичный чат без аутентификации.** Любой посетитель может расходовать GPU.
   На сервере ограничьте доступ средствами nginx (SSO вуза, basic auth, VPN)
   или поставьте приложение за шлюз Института.
2. **Pickle-файлы индексов.** `chunks_data.pkl` и `bm25_index.pkl` загружаются
   через `pickle`, который исполняет код. Каталог с индексами должен быть
   доступен только на запись процессу индексации, не пользователям.
3. **Prompt injection.** Тексты прецедентов и поля формы попадают в промпт.
   Модель может последовать инструкции из документа. Смягчение: ответы
   проверяются на ссылки на нормы и номера дел, документы всегда помечаются
   как черновик; не подключайте инструменты с побочными эффектами.
4. **Персональные данные в логах.** `query_logs` хранит текст запроса.
   Ограничьте доступ к БД, включите срок хранения и очистку (см. ниже).
5. **Один процесс.** FAISS и модель живут в памяти; несколько worker-процессов
   удвоят потребление RAM/VRAM. Запускайте `uvicorn --workers 1`.
6. **Сессии в памяти.** При перезапуске история теряется; для промышленной
   версии нужен Redis/БД.

## Эксплуатационные требования

### Обязательно на сервере

```dotenv
ADMIN_TOKEN=<длинная случайная строка, 32+ символа>
CORS_ORIGINS=https://pravo.chelgu.ru
TRUST_PROXY=true            # только за nginx
DOCUMENTS_ENABLED=false     # включать после настройки прав на каталог
```

Сгенерировать токен:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

### Права на файлы

```bash
chown -R legal:legal /var/lib/legal-assistant
chmod 750 /var/lib/legal-assistant
chmod 640 /var/lib/legal-assistant/query_logs.db
```

Каталог `stored_documents` — только для пользователя приложения. Резервные
копии шифруются (см. `docs/DOCUMENT_STORAGE.md`).

### Очистка логов

```sql
DELETE FROM query_logs WHERE created_at < datetime('now', '-90 days');
VACUUM;
```

Запускать по cron раз в месяц. Для экспертных оценок срок можно увеличить,
предварительно обезличив `query_text`.

### Проверки перед публикацией

```bash
# 1. Нет ли секретов в репозитории
git grep -nE "sk-[A-Za-z0-9]{10,}|password|secret" -- . ':!.env.example'

# 2. Админка закрыта
curl -i https://<host>/api/logs            # ожидается 401

# 3. Заголовки
curl -I https://<host>/ | grep -i "content-security-policy\|x-frame"

# 4. Лимит
for i in $(seq 1 70); do curl -s -o /dev/null -w "%{http_code}\n" https://<host>/api/health; done
```

## Модель угроз (кратко)

| Угроза | Вероятность | Влияние | Мера |
| --- | --- | --- | --- |
| Кража запросов пользователей | средняя | высокое | токен, HTTPS, ограничение доступа к БД |
| XSS через имя документа | низкая | среднее | экранирование, CSP |
| Отказ в обслуживании через LLM | высокая | среднее | rate limit, семафор, таймауты |
| Подмена индекса | низкая | высокое | права на каталог, контроль хешей при деплое |
| Утечка API-ключа LLM | низкая | высокое | `.env` вне Git, права 600 |
| Prompt injection | средняя | низкое/среднее | валидация ответа, дисклеймер, отсутствие инструментов |
